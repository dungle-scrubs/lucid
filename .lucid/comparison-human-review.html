Comparison

Lucid vs. Human Review

Two tools that found the same problem and the same fix, then made opposite bets about who holds the pen, what is under review, and whether the review leaves a record.

Human Review v0.4.0 Lucid v0.4.0 Both local, no account, no cloud

The same idea

Both start from one complaint: giving an agent feedback in chat is serial and lossy. You type "in the third paragraph, change X to Y", the agent regenerates the whole thing, and you re-read it to check whether it understood. Most of what a review costs is that round trip, one message at a time.

Both reach the same fix. The agent writes or points at a file, a browser opens it, you mark up as many places as actually need changing, and you send the whole batch back in one pass. The agent receives located feedback, applies it, and the page refreshes for another round. Both are harness-agnostic through a CLI plus a skill, both run entirely on your machine, and both target the same terminal agents.

The agreement ends at "open it in a browser and send a batch back." Everything after that is a different product.

The bet each makes

1Who holds the pen

Human Review trusts your fingers. You correct the sentence yourself, and the agent's only job is to carry that exact wording into the source - Markdown, MDX, TSX. The agent is a transcriptionist. It cannot misunderstand your fix because you made the fix.

Lucid keeps the pen with the agent. Your note says this is wrong because X, and the agent rewrites. The agent is an author you are editing. Direct editing is faster for small copy fixes and never misreads intent, but it cannot ask the agent to rethink a section - you can only override words. Comment-and-revise is slower per fix, but the agent can restructure, and the review stays a dialogue instead of a marked-up manuscript.

2What is on the table

Human Review reviews things that already exist: your files, and - this is its distinctive move - your running app on localhost. It walks your browser edits back into the code that renders the page. It is a review tool for product you are building.

Lucid reviews a thing the agent just wrote. Its README is explicit that it is not for reviewing code or your repository's source; it is a presentation layer for the agent's response. The two overlap only where an agent's response happens to be an HTML or Markdown file. By default they point at different objects.

3Whether there is a record

This is the widest gap, and it is deliberate on both sides. Human Review's feedback is a transient batch: poll, apply, acknowledge, gone. Lucid treats the review as a first-class, committed object - an append-only log, version snapshots, the full annotation and conversation history, co-located with the artifact and meant to travel in git. You can reopen a review next week, or on another machine, and the state is re-derived from the log.

Human Review is a light utility you can install in five seconds. Lucid is a review system whose cost is a compiled binary and a larger surface to learn. The record is most of what you are paying that cost for.

Which fits

Reach for Human Review

You want to fix copy and layout yourself rather than describe the fix.

You review a live localhost page and want edits to land in the source behind it.

You want something you can run with npx and no setup, and you do not need review history.

Reach for Lucid

The agent's response is itself the document under review, and you want it revised, not transcribed.

You need decisions and questions as first-class, and an Approve signal the agent obeys.

You want the review committed, resumable, and open across many artifacts in one window.
