# Claude, Pi, and Muse interactive integration capabilities

Research for [Establish Claude, Pi, and Muse interactive integration capabilities](https://github.com/dungle-scrubs/lucid/issues/255). Produced inline by the parent Codex session on 2026-09-11. Installed versions observed: Claude Code 2.1.268, Pi 0.85.1, Muse 1.1.1-R2514.1. No live interactive conversation was resumed or messaged.

## Finding that changes the design question

There is no single verified live-attachment mechanism across these harnesses. **Documented:** Pi extensions can submit user feedback into their current session; Claude hooks include an idle reawakening mechanism. **Observed:** Muse exposes session-message send, but its accessible help does not settle the delivery and presence contract. The connection decision must distinguish process presence, registered listener, and delivery acknowledgement. Sources: [Pi extensions](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md), [Claude hooks](https://code.claude.com/docs/en/hooks), and installed `muse session-message --help`, checked 2026-09-11.

## Limits that must survive into the design

**Pi, documented:** RPC mode creates a runtime with a machine channel. Its get_state response is useful for a runtime the caller owns, but the inspected RPC contract does not establish attaching RPC to a pre-existing TUI. The shipped file-trigger extension demonstrates an external event waking the current runtime; it is an example, not a durable exactly-once delivery contract. Sources: installed Pi 0.85.1 `docs/rpc.md` and `examples/extensions/file-trigger.ts`, corresponding [official RPC docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md) and [example](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/file-trigger.ts).

**Muse, observed:** `muse serve --help` specifies a stdio host whose client owns stdin/stdout and is its only connection. Creating this host is not evidence of attachment to an existing TUI. The experimental MSP schema distinguishes point-in-time session/read from view subscriptions. Neither observation establishes the native session-message service's liveness or wakeup guarantees. Sources: installed CLI help and generated MSP schema, version above.

**All three, unverified:** no end-to-end probe here proves identity registration, busy and idle feedback, listener loss, process exit, and same-history continuation together. These are explicit acceptance tests for later implementation, not current support claims. Process identity must remain distinct from session lifecycle events and from a listener's acknowledgement.

## Decision context

The next decision must specify a supported connection per interface, installation/reload behavior, and what evidence authorizes each state. It must not replace same-session continuation with a new conversation when a capability is unverified. Queue ownership, acknowledgement, failure reporting, and user-visible states remain the later tickets' decisions.

## Muse native-process follow-up, 2026-09-11

Producer: the parent Codex session. The user requests Muse, not Anthropic, for any further model review. These probes required no reviewer model: Muse's native echo provider exercised the TUI and saved-session lifecycle. Shell and write tools were disabled. Only new synthetic sessions in a temporary workspace were operated; no personal session was read or messaged. The first launch required trusting the verified empty test folder. That is a one-time setup effect in the test workspace, not a global integration install.

**Observed:** session-message list with default settings returned exit 1 and external_agent_ingress_closed. After the public configuration and messaging pages yielded login-only content, a targeted search of the installed signed binary found the experimental feature setting MUSE_EXPERIMENTAL_EXTERNAL_AGENT_INGRESS=on. Setting it only for the probe command enabled discovery. This is an observed experimental switch, not a documented stable integration contract. Neither the user configuration nor the running test session's environment was rewritten.

| Probe | Observed result | Consequence |
| --- | --- | --- |
| Discover the isolated TUI | Returned its exact native session ID, session name, and workspace label. | Native session discovery works with the experimental ingress setting. The label is not full working-folder provenance. |
| Send from an external CLI process | Refused with sender_unverified and an empty receipts list. | Discovery does not authorize external delivery. Idle wakeup and acknowledgement are not established. |
| Send directly from the signed native binary, with local-session messaging enabled too | Same sender_unverified refusal. | The wrapper alone does not explain the refusal. No attempt was made to forge sender identity or bypass admission. |
| Suspend the owning TUI process | Session-message list still returned it, while Lucid's process-owner probe reported the process present. | Discovery and process presence do not prove that a listener can respond. |
| End the owning TUI process | The session disappeared from discovery. | This isolated orderly/terminated process transition is observable. It is not an exhaustive stale-registry or crash guarantee. |
| Resume the alias-path fixture through HCN | Refused because the stored /tmp workspace spelling differed from the /private/tmp working path. Supplying the alias as cwd or as a native workspace argument did not repair this probe. | Preserve and validate native working-folder provenance. Equivalent filesystem paths are not sufficient evidence that Muse will accept resume. |
| Create a second fixture with the canonical path, end its TUI, then resume through HCN | Process exited successfully. Native export contained two assistant responses, the original and resumed probe markers, in the same session ID. | Real native-record continuation works for this canonical-path echo fixture. It is stronger than invocation inspection, but does not prove model memory recall or all resume cases. |

Reproduction surfaces were the installed Muse 1.1.1-R2514.1 TUI, session-message list/send, export with an explicit probe ID, and HCN run muse with resume, cwd, no-write and no-shell. The echo provider was used for both sessions. SIGSTOP/SIGCONT were applied only after identifying the first test process, with restoration in a finally block. Each shutdown checked that the target process held that exact synthetic session's lock. Both TUI processes were ended after the probes.

Local ignored evidence under artifacts/evidence/interactive-artifact-wayfinder/: muse-presence-probe.mjs/json, muse-probe-termination.json, muse-headless-resume*.ndjson, muse-canonical-headless-resume.ndjson, muse-canonical-after-resume.json, and muse-resume-proof.json. The last receipt records one native ID, two turns, and both response markers. HCN reported identity authority caller-assigned; independent native export supplies the pre-existing-record evidence. Echo also repeated HCN's question-protocol teaching, so the normalizer classified the otherwise successful echo turn as awaiting-input. That classification is not evidence that a human question blocked resume.

The native CLI help documents export as an offline read and resume as a stored-session operation. The [first-party extending reference](https://dev.meta.ai/docs/muse-code/extending) describes headless continuation and workspace mismatch refusal. The [first-party messaging page](https://dev.meta.ai/docs/muse-code/session-messaging) remained inaccessible. Binary inspection supplies the provenance of the experimental switch; the actual CLI results supply the refusal and discovery evidence.

**Still unverified:** a supported way for Lucid's external process to satisfy sender admission, live input delivery while idle or busy, durable delivery acknowledgement, and exact listener health. Do not expose a working reconnect/send action on the strength of session-message help or discovery alone. A connection design can investigate an integration running inside the originating session, but these probes did not implement or validate that alternative.
