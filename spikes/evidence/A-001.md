# A-001 - Persistent headless session: PASS

Date: 2026-08-10 · claude CLI 2.1.226 · macOS (pro) · model: sonnet
Script: `spikes/a001-session.ts` · Raw events: `spikes/evidence/a001-raw.ndjson`

## Verdict

PASS on every criterion. One process served three turns over
`-p --input-format stream-json --output-format stream-json --verbose
--include-partial-messages`; token deltas streamed each turn; a message
sent mid-generation was queued and became the next turn; the session
resumed with full memory after close.

## Observations

- **One process, many turns.** Single spawn (pid 94283), three
  user messages in over stdin, three completed turns out. Exit 0 on
  stdin close.
- **Session identity.** `system/init` is re-emitted at the start of
  EVERY turn, same `session_id` each time (eb04301d-...). A consumer
  should treat init as turn-start metadata, not a once-per-session event.
- **Turn boundary.** Each turn ends with a `result` event
  (`subtype: success`, per-turn `num_turns: 1`, full text in `result`).
  This is the reliable turn delimiter for openSession().
- **Token deltas.** `stream_event`/`content_block_delta` present every
  turn (chunky for short replies - deltas are chunk-level, not strictly
  per-token; granularity claim "token" holds in the protocol sense of
  incremental within-message output).
- **Mid-turn send: QUEUED.** A user message written to stdin at delta 3
  of turn 2 (the counting turn) produced no error, did not interrupt or
  contaminate turn 2 (counting completed cleanly), and was answered as
  turn 3 ("beta done"). Disposition for headless-session mid-turn input
  is `queued` - exactly the input.mode=queue semantics the protocol
  wants. No steer without interrupt(), which the CLI surface does not
  expose (SDK-only).
- **Continuity after close.** `claude -p --resume <sid>` recalled
  mid-conversation content ("beta done") - and the result's
  `session_id` was the ORIGINAL id, i.e. this resume did not rotate
  identity. Rotation behavior is A-005's question; this data point says
  same-id continuation happens at least sometimes.
- **Housekeeping.** `system/hook_started`/`hook_response` events from
  user-level hooks appear in-stream; a `rate_limit_event` frame appears
  too. The normalizer's decoder must tolerate unknown system subtypes.

## Consequences for the plan

- `openSession()` for claude is viable exactly as designed (M3.2):
  turn streams delimited by `result`, `send` queues mid-turn.
- `capabilities.session = true`, streaming granularity `token` for this
  invocation - descriptor pins these flags (M2.1).
- Escape hatch 1 not needed.
