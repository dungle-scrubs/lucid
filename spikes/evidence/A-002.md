## C1 - mid-turn boundary injection (PASS)

The human-side driver queued a message AFTER the first PostToolUse of turn 1.
It was delivered at the next tool boundary WITHIN the same turn, and the model
acted on it. From `pty.log` (verbatim, escapes stripped):

```
⏺ Write(work/one.txt)
  ⎿ Wrote 1 line to work/one.txt: ready
  ⎿ PostToolUse:Write hook returned blocking error
  ⎿ HUMAN FEEDBACK (mid-turn): Also create work/four.txt containing exactly
     extra. Then say exactly: FEEDBACK-ONE-APPLIED.
```

The lucid `PostToolUse` hook returned `{decision: "block", reason: "HUMAN
FEEDBACK (mid-turn): ..."}` on stdout; claude surfaced it as a blocking
error carrying the human text, and the model produced `FEEDBACK-ONE-APPLIED`
(`driver-events.log: FEEDBACK_ONE_VISIBLE`). `delivery.log` records one
`delivered_by: PostToolUse`. This is genuine mid-turn delivery, not a
next-turn queue.

## C2 - project-hook co-run, not exclusivity (PASS)

`settings.json` declared TWO distinct `PostToolUse` blocks: lucid's
(`lucid-inject.sh`) and a benign pre-existing project block
(`other-project.sh`, marker only). BOTH fired on BOTH tool events:

```
hooks-fired.log (lucid):  PostToolUse Bash @967, PostToolUse Write @970
co-run.log (other):       PostToolUse Bash @967, PostToolUse Write @970
```

So `--setting-sources project` loads and runs ALL project `.claude` hooks;
lucid does NOT get exclusive ownership of an event. **Consequence for M2.3
(`D-010`):** the adapter MUST detect and coexist with pre-existing project
hooks (never assume it is the only PostToolUse hook), and its injection
decision must compose with, not clobber, other hooks' output.

## C3 - transcript flushes at the turn boundary, not during work (CONFIRMED)

The sampler polled the transcript `.jsonl` size+mtime every 200ms. During the
entire tool-free reasoning turn (turn 2, window `970997..972140`) the file was
**frozen**: size `16467`, mtime `...967` (a *turn-1* timestamp). The first
sample AFTER the turn completed jumped to size `17174`, mtime `...972` - the
turn's content was written in one burst at the boundary.

Meaning: during a tool-free turn, (a) **zero hooks fire** (`hook_counts` shows
no PostToolUse/Stop in the turn-2 window) and (b) **transcript mtime is stale**
by the full turn duration. Both candidate liveness signals - a hook-driven
heartbeat and transcript-mtime - have an unbounded gap exactly when the agent
is busy reasoning. A turn longer than the 15s lease would be wrongly declared
dead by either. This is the direct evidence for `D-009`: liveness MUST be a
**held presence lock** (kernel-released on death), not a beat or a file clock.

Caveat (honest): sonnet answered the reasoning prompt in ~1-5s, so the window
was short. The result is structural, not duration-dependent - the flush is a
single turn-boundary burst and the mtime froze for the whole turn regardless of
length; a longer turn only widens the same gap.

## Secondary observations

- **SessionStart announce: CONFIRMED.** `announce.log` records session
  `e34feb51-...` with its concrete transcript path at startup, zero agent
  cooperation - the adapter's attach signal.
- **Isolation (`D-025`): CONFIRMED end-to-end.** `--setting-sources project`
  + `HERDR_ENV` unset ran a full multi-turn session with no global-hook hang.
- **Startup chrome changed 226 -> 227.** The TUI renders prompts with
  cursor-column escapes between words (`Allow<ESC>[9Gexternal...`), so literal
  expect matches fail; the driver matches escape-tolerant regexes and
  single-token sentinels. (Harness note, not a contract.)
- **Stop hook did not fire in this run.** Only PostToolUse fired; consistent
  with the 226 "Stop-path partial" finding. PostToolUse boundary injection is
  the load-bearing mode and is proven; M2.3 should treat Stop-hook turn-end
  delivery as best-effort, not a guarantee.

## Consequences for the plan (unblocks Phase 2 / M2.3)

- The injection contract holds on 2.1.227 - M2.3 can build the `inject` hook
  on PostToolUse boundary delivery, test-first against these fixtures.
- Project-hook coexistence is REQUIRED (C2), confirming `D-010`; it is not a
  droppable simplification.
- `D-009`'s presence-lock is justified (C3): mtime and hooks both gap during
  tool-free work.
- No escape hatch triggered; no regression needed. SPIKE passes.
