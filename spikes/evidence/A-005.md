# A-005 - Headless-turn resume semantics: FAIL (one clause refuted, and it matters)

Date: 2026-08-10 · claude CLI 2.1.226 · macOS (pro) · model: sonnet
Scripts: inline shell (part 1), `spikes/a005-live.sh` (part 2)

## Verdict

Split. Clause 1 (id rotation discoverable/re-bindable) holds - and is
SIMPLER than assumed: there is no rotation. Clause 2 ("resume against a
live session never appends") is REFUTED: a concurrent `--resume` of a
live session appends straight into the live conversation with no lock,
no refusal, no fork. Recorded as `fail` because the assumption as
written is false, and the false half is load-bearing for single-writer.

## Part 1 - rotation/re-binding (holds, simplified)

Session 2296352c-..., caller-assigned via `--session-id`:

- turn 0 (`--session-id`): result sid = original id, "ok"
- resume 1 (`--resume <orig>`): sid = original id, recalled the word
- resume 2 (`--resume <orig>`): sid = original id, recalled BOTH the
  word AND resume 1's reply ("ok/pomegranate") - resumes append to one
  continuous conversation, they do not fork from the original point
- store: exactly ONE file, `<orig>.jsonl`, growing across resumes

**Rule for the normalizer:** claude identity is caller-assigned and
stable; always resume the same id; `result.session_id` confirms it.
No `allowRotation` handling needed for claude (v1's rotation scar does
not reproduce on 2.1.226). `--fork-session` exists for deliberate
branching and is the only forking path we invoke on purpose.

## Part 2 - resume against a LIVE session (refuted)

Setup: persistent stream-json session (5132e4f2-...) held open by a
live process; turn 1 complete; process alive and idle.

Attempt: `claude -p --resume <live-id> "Reply with exactly: intruder"`
from a second process, while the first was alive.

Observed:
- The intruder turn SUCCEEDED: same session_id, `is_error: false`
- The live session's transcript grew 9 -> 15 lines; "intruder" content
  written into the LIVE session's store file
- No lock, no refusal, no fork, no error on either side; the live
  process stayed alive and unaware

**Consequence:** the harness does NOT protect the single-writer
invariant, even minimally. Two writers on one native claude session is
trivially possible. lucid's presence gate + lease/epoch fencing is the
ONLY defense - the forbidden-path rule ("no headless spawn while
presence holds") and its oracle are load-bearing, not defensive depth.
Any dev script or future code path that resumes a session id MUST go
through lucid's gate.

(Note: a docs-level claim that resuming a "background agent" session is
refused did not reproduce for a plain live `-p` stream-json process -
that guard evidently covers a different feature. Trust this measurement
over the docs.)

## Consequences for the plan

- M2.1 (claude descriptor): identity = caller-assigned, stable across
  resumes; drop rotation handling; `--fork-session` only for deliberate
  branch semantics.
- M4.4 / M5.3: the presence-gate refusal and the forbidden-path test are
  promoted to load-bearing; risk-register likelihood for the two-writer
  accident raised (harness offers no backstop).
- A-002/A-003 interactive spikes should re-run the interference attempt
  against a TTY-interactive session for completeness (expected same
  result; the gate does not depend on it).
